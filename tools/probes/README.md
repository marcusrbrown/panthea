# tools/probes

Hardware, provider, renderer, and sandbox probes live in `tools/probes/<name>/`, each with a README recording the method and results.

The M0 renderer probe app (`apps/probe-renderer`) was removed on 2026-09-28; the repository has one Tauri app, `apps/desktop`. The [renderer-webgl2](renderer-webgl2/README.md) results stand as evidence, and the app source is at commit `ce9e5a4` (`git show ce9e5a4:apps/probe-renderer/...`). The [coexistence](coexistence/README.md) and [inference-baseline](inference-baseline/README.md) runs used its packaged `.app` as the renderer load, so their rerun commands need that commit or a replacement load.

- [webgpu-wkwebview](webgpu-wkwebview/README.md) — WebGPU-in-WKWebView probe via an unsigned Swift WKWebView script (not a packaged app).
- [renderer-webgl2](renderer-webgl2/README.md) — packaged Three Flatland scene on the WebGL2 backend (D25): 59 fps, 28 ms p50 / 31 ms p95 click-to-visible latency measured on the packaged `.app` (14/14 real clicks), koota CSP constraint (ADR-0002); with `three@0.185.1`'s `WebGPURenderer`, synthetic context loss/restore both occur but the renderer instance stays latched (`_isDeviceLost` never cleared) — automatic same-instance recovery is unavailable in this build, app-managed renderer/canvas reconstruction is untested, sleep/wake is untested. *2026-10-02 note:* reconstruction is now implemented in `apps/client` (`App.tsx` remounts `SceneHost` on loss, with a fresh canvas and renderer) and was verified in the packaged debug build by a forced context loss; a verified presented-frame gate, bounded retries, and a real sleep/wake run remain open ([device-loss learning](../../docs/solutions/integration-issues/three-webgpurenderer-device-loss-latch-2026-09-27.md), [ADR-0002](../../docs/decisions/0002-renderer-backend.md)).
- [backend-lifecycle](backend-lifecycle/README.md) — Bun sidecar under Tauri: supervised lifecycle, crash restart, no orphan, no double time advancement (ADR-0003).
- [inference-baseline](inference-baseline/README.md) — local model profile measured for schema validity, latency, throughput, and memory with the renderer running: llama3.2:3b @ 4k is the baseline (p95 1.8 s), but 27 characters at parallel=1 already exceed the 30 s cadence threshold (ADR-0005).
- [art-local](art-local/README.md) — local pixel-art generation: stable-diffusion.cpp (`sd-server`, SD 1.5 Q8_0 + pixel-art LoRA, `--diffusion-fa` required — ~5x slower without it) is the recommended base arm at 37.3s/image p50, 2320 MiB peak RSS (512x512, 12 steps) — Q4_0 is smaller/measured too but its LoRA application was verified empirically unreliable (owner-flagged, confirmed via fixed-seed with/without comparison) and is not a valid pixel-art measurement; Draw Things (optional add-on, same LoRA, f16 precision) measured 6.5x faster but the comparison is precision-confounded — the matching f16 sd.cpp + LoRA run reproducibly crashes this build (a confirmed stable-diffusion.cpp bug applying LoRA to non-quantized weights on Metal), and Draw Things is macOS-only with no HTTP-level model/LoRA selection or in-flight cancellation (ADR-0007).
- [sandbox](sandbox/README.md) — QuickJS and Lua adversarial fixture matrix for the generated-code runtime: 0 escapes across every external-capability and malformed-input fixture after a 3-round Proxy/property-descriptor argument-capture fix; QuickJS is recommended, with the outer subprocess wall-clock/RSS supervisor — not the interpreter's own `setMemoryLimit`, confirmed soft — as the real memory boundary (ADR-0004).
- [provider-matrix](provider-matrix/README.md) — hosted provider adapters (OpenCode Go, OpenAI/Anthropic by contract), a fallback chain, and an offline-mode packet-capture proof; OpenCode Zen's `zen/v1` free tier is a scope note (unconditional 403 from a non-public service), so the OpenCode arm is Go, free models first (ADR-0005).
- [coexistence](coexistence/README.md) — renderer + llama3.2:3b + stable-diffusion.cpp together on 16 GB: **inconclusive** — no candidate policy clears the ≤25% LLM p95 penalty bar with verified data. Unconstrained (+78%) and the global mutex hypothesis (+1759%, LLM requests waiting out a full ~25s image job) fail from the original run's numbers (not independently re-verifiable; their raw per-request records did not survive); a re-measured admission-controlled queue at free+inactive ≥ 3 GiB — the prior run's apparent winner — now measures +148% under corrected, success-filtered instrumentation, while a stricter 5 GiB gate starves image generation to 0 completed images on this machine's pre-existing swap floor. Next: re-verify B/C/D@5GiB and test an intermediate threshold between 3–5 GiB (ADR-0003/0005/0007's shared memory-policy wording should reflect "inconclusive, pending further measurement," not a settled recommendation). *2026-10-02 note:* only one pair is comparable, the baseline against the 3 GiB admission queue: LLM p95 1242 → 3086 ms with 6 images completed, which does not support that policy. The unconstrained, global-mutex, and 5 GiB results above were measured in a different session, so they have no comparable baseline and no verdict; none is adopted or ruled out. The next step is the M2-exit workload baseline, then each candidate against it before M4 enables concurrent image generation ([ADR-0005](../../docs/decisions/0005-model-providers.md)).
- [catchup-bench](catchup-bench/README.md) — one simulated hour of catch-up on the immutable Unit 7 pack (7 gods, 20 mortals), on-disk SQLite, fixed seed: per-phase timing, row and byte counts, and CPU profiles for 4 and 20 mortals, fresh and aged. Baseline on main `d566975`: 4.96 s fresh and **22.5 s aged** for 20 mortals (targets: 5 s, every chunk under 250 ms); the time was routine planning's petition scans (36% aged), checkpointing (37%) and the trace's writes (18%), driven by random trace ids and the unpruned petitions, not the projection double-reduce (1.7%), the event-list recopy, or the summary. After two fixes (time-ordered ids, a petition index): **3.81 s aged, 2.97 s fresh, worst chunk 123–148 ms aged** (every chunk and the ending commit counted), with the same events, trace, and projection.
- [god-latency](god-latency/README.md) — what one seven-god request costs a local qwen3 8B at a 4K context on Ollama, from the server's own accounting (prefill, decode, load) and with the server's one-slot prompt cache in play: a cold 2,200-token request is about 15 s of prefill and 3.5 s of decode, an identical resend about 60 ms, and the first request after a load 23–28 s. Ordering a request from what never changes to what changes every tick raised the start the seven gods share from 8 to 1,279 characters and cut the rotation's median prefill about 12% (9.0 to 7.9 s); the router's attempt timeout is now 45 s (cold p95 and half again), where 15 s cut off 20 of 33 requests in an 8-minute episode.
- `shared` — harness code shared by every probe: environment capture, README report rendering, timing/percentile helpers, and the action-proposal schema (`@panthea/tools-probes-shared`).
